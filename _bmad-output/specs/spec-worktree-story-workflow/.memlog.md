- (note) Existing scripts/v2/story-branch.sh and _bmad/custom/story-branch-workflow.md define feat/{story-key} branches from origin/v2 but operate in the current checkout; this change extends rather than replaces their policy.
- (constraint) Keep v2 as the integration branch, never mutate another worktree, preserve a failed unit for inspection, and keep merge and push explicit after review.
- (capability) CAP-2: A fresh story worktree provisions the local BMad runtime reproducibly before a manual BMad workflow is started.
- (capability) CAP-1: Start a story or bug from the V2 integration baseline in a new branch and deterministic adjacent worktree without changing the integration checkout.
- (direction) Replace the mandatory per-story branch workflow with a dedicated Git worktree per manual HatCast story or bug so multiple units can progress concurrently on one machine.
- (event) Coherence validation passed: four capabilities contain intent and testable success, constraints bend design, non-goals are explicit, and no unsupported implementation mechanism was selected.
- (event) Preservation validation passed: the user request for isolated manual story worktrees, the existing branch-only policy, the runtime reproducibility failure, and explicit review-gated integration all land in SPEC or its companion.
- (decision) D-1: Commit only feature branch and baseline commit; derive and validate the worktree path locally so machine-specific paths never enter story metadata.
