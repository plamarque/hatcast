# Revue de réalité — architecture Avent

Verdict : le cadre Angular / API Kotlin / PostgreSQL et la capture PostHog côté navigateur sont ancrés dans le dépôt ; plusieurs raccordements nécessaires ne sont pas encore établis.

1. **Élevé — Le circuit de notification actuel est centré sur un spectacle.** `NotificationDispatchContext.kt` exige `eventId` et `seasonId` non null ; le calendrier n'a pas nécessairement de spectacle ou de saison. Le dispatcher, les modèles, préférences et marques devront être étendus ou adaptés pour un événement de calendrier de troupe, sans inventer un spectacle fictif. L'AD-5 ne doit pas laisser supposer que le raccordement est déjà disponible.
2. **Élevé — Déclencheur et disponibilité historique non établis.** Le code de rappel existant (`AvailabilityPendingReminderJob.kt`) utilise `@Scheduled` dans le processus Spring ; le workflow `deploy-v2-cloud-run.yml` ne spécifie ni instance minimale ni déclencheur externe. Les réglages déployés réels ne sont pas accessibles depuis ces seuls fichiers. Aucun mécanisme trouvé ne permet d'établir si un contenu déployé était disponible à 9 h après une interruption. Conserver ce point comme préalable bloquant à une conception exécutable, en particulier lors d'une publication tardive.
3. **Élevé — Portraits.** `avatar/AvatarConfig.kt` échoue explicitement si le stockage GCS est choisi ; seule l'implémentation locale y est raccordée. L'architecture ne peut supposer un stockage d'avatars GCS privé opérationnel ; choisir un moyen de servir les portraits qui respecte les règles d'autorisation, les caches et le cycle de vie Cloud Run.
4. **Moyen — Environnements.** Le dépôt prévoit un profil `dev` PostgreSQL avec seeds et un profil `cloud` sans seeds, ainsi que H2 pour offline/E2E. Il ne prouve pas à lui seul que le serveur distant de développement utilise une base, des canaux de notification et un projet PostHog distincts de production. Vérifier avant usage ; qualifier la convention comme exigence, pas constat.
5. **Moyen — Mesure.** `ProductAnalyticsService` identifie les utilisateurs et capture côté navigateur ; il faut expliciter l'identifiant stable utilisé et la déduplication des événements de réponses en cas de nouvelles tentatives, tout en documentant les interruptions qui empêchent l'émission. Le comptage exact reste la base.
6. **Moyen — Autorisation.** `TroupeAccessService.requireActiveMember` contourne la vérification d'adhésion pour l'admin plateforme ; le contrat prévoit correctement une règle plus stricte, mais l'implémentation devra appeler le contrôle d'adhésion réel ou équivalent au lieu de réutiliser seul ce garde.
7. **Moyen — Base locale.** PostgreSQL correspond au runtime cloud/dev, mais `application-offline.yml` et `application-e2e.yml` utilisent H2 ; les migrations et contraintes choisies doivent permettre la recette locale prévue par le dépôt ou expliciter une solution compatible.
