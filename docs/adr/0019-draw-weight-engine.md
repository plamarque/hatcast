# ADR-0019: Draw weight engine (V1 parity, factor pipeline, golden regression)

- **Status:** Accepted
- **Context:** Epic 6 delivered MVP weighted draw for V2 (`AvailabilityChanceCalculator`, `CompositionDrawService`, draw-time snapshots in **6.14**). The algorithm is business-critical for fairness (**FR19**, **FR20**, **FR24**) and must remain explainable: **displayed % must use the same weight path as the server draw**. V1 production (`legacy/chancesService.js`) ships only past-participation malus today, but V2 will need pluggable factors (gender parity, volunteer bonus, category compartment hardening, etc.) without silent formula drift. Investigation **2026-06-04** confirmed core formula alignment but documented intentional gaps (category compartment **G-01**, replay harness **G-04**) and V2-only extensions (snapshots **E-01**, history modes **E-02**). Product context: [Sprint Change Proposal Epic 19](../../_bmad-output/planning-artifacts/sprint-change-proposal-2026-06-04-epic19-draw-weight-engine.md).
- **Decision:**
  1. **Normative V1 spec** — [`docs/v2/technical/draw-weight-engine-v1-spec.md`](../v2/technical/draw-weight-engine-v1-spec.md) is the authoritative contract for V1 parity, golden tests, and delta tracking. SPEC and DOMAIN reference this document and this ADR; they do **not** duplicate the full formula.
  2. **Invariant** — **Displayed % = draw weights:** one calculator pipeline (`AvailabilityChanceCalculator` today) serves weighted draw selection, Dispos **Tous %**, and Équipe explainability. Any refactor must keep this invariant or amend this ADR with updated golden coverage.
  2b. **Dual explainability visibility gates (2026-06-09):** The **calculator pipeline is shared**, but **visibility is surface-specific:**
     - **Dispos gate** — published event (availability open); independent of `event_compositions` draft state.
     - **Composition gate** — Équipe slot assignments and slot-level odds; members after `publishedAt` or `validatedAt`; organizers with `canManageComposition` on draft.
     - Implementations: `DisposExplainabilityAccess` + `CompositionExplainabilityAccess` (names illustrative). Amending gates requires PRD FR24 alignment, not formula changes. SCP: [`sprint-change-proposal-2026-06-09-explainability-gates-dispos-equipe.md`](../../_bmad-output/planning-artifacts/sprint-change-proposal-2026-06-09-explainability-gates-dispos-equipe.md).
  3. **Factor pipeline (Wave B+)** — Future weights compose as `finalWeight = base × Π factorMultiplier`. **DEFAULT (19.8):** `[CategoryCompartmentFactor (equity_tag), PastParticipationFactor]` — compartment is always on (`multiplier = 1.0`; scoped `pastSelectionCount` carries the effect); past-participation malus unchanged. Interface and registration: stories **19.5–19.7** (shell + breakdown), **19.8** (compartment). Optional formula toggles deferred to **19.16+**. **Production runtime** continues to use `DrawWeightPipelines.DEFAULT` until **19.18** wires persisted troupe formulas; implicit **system V1 formula** = same factor set (`[equity_tag, past_participation]`) — see Wave D spec § System V1 formula.
  3b. **Wave C (19.9+)** — `ImmediateReplayFactor` (`immediate_replay`) implemented: same trigger as **6.20** warning; modes `EXCLUDE` / `MALUS`; **absent from DEFAULT** until troupe formula wiring (**19.16**). Golden path: `draw/golden/immediate-replay/`.
  3c. **Wave C (19.10)** — `RoleRequestFactor` (`role_request`) implemented: **bonus only** for `unfulfilledRoleRequestCount` (past validated shows, same compartment, available for role but not selected); interim formula `min(1 + n, 10)`; **absent from DEFAULT** until **19.16**. Golden path: `draw/golden/role-request/`.
  4. **Non-regression** — Story **19.2** implements a golden JSON fixture suite under `services/api/src/test/resources/draw/golden/` per normative spec § **Golden test contract (19.2 handoff)**. Wave A golden authority = spec + ADR, **not** `scripts/replay/chancesLogic.js` alone (**G-04**).
  5. **Draw-time snapshots (6.14)** — Persisted `%` at draw opening (`event_draw_chance_snapshots`) store draw-time odds, not formula id. Formula/policy id on snapshots is deferred to **19.22** (Wave D). Note **E-04**: opening snapshot `%` uses `openingCrossRoleExcluded`; per-step `steps[]` `%` evolves during the same request — both behaviours remain documented and test-covered (**19.2** / **19.3**).
  6. **Wave D — formulas & policies (normative summary)** — Troupe-scoped **`DrawFormula`** catalogue and **`DrawPolicy`** (`TROUPE` \| `SEASON` scope) with `defaultRule` + `categoryRules[]` resolved via **`event.category`** (slug, **17.7** — not `templateType`). **Authority:** [`docs/v2/technical/draw-formulas-policies-spec.md`](../v2/technical/draw-formulas-policies-spec.md) (mirrors V1 spec pattern). Decisions:
     - **Catalogue** — troupe admins CRUD formulas (`DRAFT` \| `PUBLISHED` \| `ARCHIVED`); `factorConfig` ordered list of `{ factorId, enabled, params? }`; system V1 formula = `[equity_tag, past_participation]` matching `DrawWeightPipelines.DEFAULT`, **always** available in choice lists.
     - **Policy scopes** — troupe default + optional season override; season policy **overrides** troupe for events in that season.
     - **Resolution** — match `event.category` to `categoryRules[]` (exact slug; `null` rule = principal/unset); else `defaultRule`; else **implicit MVP default** (`CHOICE` + all published formulas + system V1 — **OQ-19-02**).
     - **Operator choice** — when resolved rule is `CHOICE` with ≥2 allowed formulas, organizer **must** pick `formulaId` at draw; no per-event policy row in MVP.
     - **Persistence** — deferred to **19.16** (illustrative tables: `draw_formulas`, `draw_policies`); APIs **19.17–19.18**; UI **19.19–19.21**.
     - **Versioning** — formula edits affect **future** draws only; **19.22** extends `event_draw_chance_snapshots` with formula id + frozen `factorConfig` + policy context (today: `%` only, **6.14**).
     - **Validation & security** — troupe isolation; unknown `factorId` → reject formula **save**; enabled but unimplemented factor → reject formula **publish**; foreign/`DRAFT`/`ARCHIVED` formula in policy → reject policy save; runtime fallback if referenced formula later unavailable (Wave D spec § Active catalogue invariant); season policy edit = **`TROUPE_ADMIN` only** (**OQ-19-05**).
     - **Production DEFAULT unchanged** until **19.18** wires runtime to persisted formula; optional factors **19.9+** remain off in DEFAULT until formula wiring.
- **Consequences:**
  - **Positive:** Auditable evolution of fairness rules; category compartment locked in DEFAULT pipeline and golden tests (**19.8**); developers can implement **19.2** without reading `legacy/`.
  - **Negative:** Normative doc maintenance burden; golden CI cost; intentional V2 multi-slug compartment vs V1 binary split remains documented (**G-01**, not a regression).
- **Documentation utilisateur:** [`docs/v2/product/draw-chances-explained.md`](../v2/product/draw-chances-explained.md) — French plain-language guide for organizers and members (what % mean, visibility, snapshots, out-of-scope Wave C/D). Technical contract remains this ADR + normative spec; the product doc does not duplicate the formula.
- **Alternatives considered:**
  - **Re-open story 6.4 code** — Rejected (SCP); hardening is Epic 19, not a rewrite of shipped MVP.
  - **Change formula without ADR + golden** — Rejected; business-critical path requires regression suite.
  - **Free-form scripting for organizer formulas in MVP Wave D** — Rejected; formulas are structured catalog entries (**19.15**).
  - **Use `chancesLogic.js` as sole golden reference** — Rejected; missing `exactSelectionProbability` (**G-04**).
