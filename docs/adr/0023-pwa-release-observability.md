# ADR-0023: Bundled client release and CI-owned PostHog lifecycle reference

- **Status:** Accepted (PO decisions, 2026-10-18)
- **Context:** Product operators need named follow-up of older clients and install/update/release-note observations. Live `version.txt` can already describe a new server while an older client still runs. Manually edited PostHog SQL variables conflict with automated production releases.
- **Decision:** Embed `semver:git_hash` from the existing release artifact into the Angular bundle. Observe that identity after authentication. Confirm update application only when a recent same-user request in browser session storage is followed by a different bundled release. After successful production deployment, an independent CI job captures a personless `hatcast_release_promoted` event dated at deployment completion and provisions only CI-owned dashboard/insight objects through documented EU APIs. Derive the target and date in SQL from retained promotion events, using earliest capture per release. Existing People name/email may appear in restricted operator tables; custom client events do not duplicate them. Notes opening captures CSS viewport with existing PostHog compatibility metadata, and loaded closing reports visible-time and scroll buckets.
- **Consequences:** No manual variable update per release and no client-side guess from an NGSW hash. Missing credentials/API access fail the observability job visibly without undoing deployment. Release history starts with instrumentation; multi-device latest-client limitations, blocked storage, unrequested upgrades and rollback interpretation are explicit. Dashboard and HogQL execution need real PostHog verification after local mock checks.
- **Alternatives considered:** Live server version fetch (mislabels stale clients); maximum client-observed version (unreliable until a new client reports); manually maintained variables (not automated); private PostHog internal variable APIs (unsupported contract); semver-distance/ordered release ledger (unnecessary for the approved days-since-latest metric); arbitrary release-note engagement threshold (not approved).
