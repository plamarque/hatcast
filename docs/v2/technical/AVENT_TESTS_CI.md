# Advent regression CI inventory

The Advent checks are seasonal. Keep their fixtures fictional and their paths identifiable; no data is taken from a shared environment. CI results are tied to the GitHub candidate revision and are not deployment evidence.

## Execution and evidence

`.github/workflows/advent-regression.yml` runs on pull requests and pushes and is also called by the V2 release workflow. Its existing `api-and-web` job runs the eight Advent H2 API classes, the Advent Angular suite and the existing privacy and configuration checks. A separate `member-shell` job runs general shell tests even if Advent-specific jobs fail. The existing `postgres` job runs the three Advent PostgreSQL classes on a disposable PostgreSQL 16 service. These checks are not added a second time to `api-test.yml` or `apps-web.yml`; those workflows retain their existing general API suite and web build respectively. The general API suite can still overlap the targeted H2 tests: that pre-existing overlap preserves its independent coverage and the release gate.

Each selected Angular suite emits a JUnit report, and each selected API and PostgreSQL class is validated from the Gradle XML. `scripts/v2/ci/check_reports.py` reports the candidate SHA, executed, failed and skipped counts and timings; it rejects missing or ambiguous suites, empty selections, skips, failures and inconsistent declared counts. Its contract tests run with `python3 -m unittest discover -s scripts/v2/ci -p 'test_*.py'`. Reports are uploaded even if a prior step fails. A failed run or absent report is not successful evidence.

The existing browser job runs Playwright, privacy, production PWA, service-worker and isolated full-stack checks. Its explicit `chromium-advent-answer` selection covers `e2e/advent-member.spec.ts` and `e2e/advent-isolation/advent-answer.spec.ts`: `--list` discovered 17 tests on the reconciled revision; listing is not execution evidence. The wider project also lists three `e2e/advent-answer.spec.ts` tests that this release job does not select. A subset of Playwright tests intercepts API responses; those tests alone do not prove the real member API journey. The standalone `apps/web/src/app/pages/advent-test/advent-test.motion.browser.cjs` and `apps/web/e2e/advent-isolation/advent-service-worker.smoke.cjs` are not selected by this workflow. The latter resets isolated test state and requires its documented local services; never run it against a shared environment.

## Retirement

When removal is explicitly requested, inventory the Advent jobs, fixtures, portraits, data retention, callers and release-gate dependencies first. Preserve general HatCast coverage: before removing the Advent workflow, relocate the independent `member-shell` job to a general web workflow. Keep the shared report validator while general jobs use it. Remove only obsolete Advent checks, and verify that no required job succeeds with an empty selection. Removal of production data or private content requires a separate decision.

## Evidence and limitations

On the earlier uncommitted working tree based on `b1d2fc5773396fbf5279f814e5b858470077a389`, Node 20.20.2 ran 119 Advent and 20 shell tests without failures or skips (2.668 s and 1.036 s respectively, XML test time). PostgreSQL 16 ran all seven tests in the three required classes, and the full API suite passed locally in 5 minutes 33 seconds. On reconciled HEAD `a84201ec0d8560e5575fd020519caa6e42c47d11`, Node 20 ran 144 Advent tests in 3.240 s and 24 shell tests in 1.196 s (XML durations), all without failures or skips. The eight targeted H2 API classes ran 55 tests and PostgreSQL ran eight tests on a disposable PostgreSQL 16 instance (3.109 s cumulative XML time), without failures or skips. Workflow changes were uncommitted during these measurements. The earlier PR's jobs also ran earlier selections, but that evidence predates reconciliation with the current release workflow. Re-run and report the checks on the final revision; a local run is not proof of GitHub Actions execution. Branch protection and repository rules must be inspected separately before claiming an enforced gate.
